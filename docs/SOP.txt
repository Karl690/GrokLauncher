SOP — programming sessions (all projects)

A session is one sitting with one specific goal. It is not the whole product and not "whatever comes up."

Start of session

State or agree:

1. Goal — one sentence.
2. Done when — what we will see on the real machine, UI, or log. Not "the code looks right."
3. Don't break — constraints that stay unless the goal changes them.

If we cannot fill Done when in one sentence, we are not ready to code.

FSD (only when meaning changes)

When a command, coordinate system, or user-visible behavior changes, write a half-page functional spec first: name, inputs, outputs, pass, fail, out of scope. A bug fix in existing behavior does not need an FSD.

While working

- Keep the change scoped to the goal.
- Do not claim done, fixed, or tested without evidence (build, flash, test, or log).
- Verify on the real target when the work is hardware, motion, or UI. A compile is not a motion test.
- Prefer one behavior per session. If we finish early, that is a new session with a new goal.

Naming

- No single-letter locals unless the declaration line has a comment saying what it is.
- Prefer a self-documenting name: float PulsesForPopoff; not float p;.
- Loop indexes may be axis, sample, row — not i unless commented.

Single-line if

One statement: keep it on one line, with a comment on that line when the reason is not obvious.

if (cond) action; /* comment */

Example: if (popOffDistance <= 0.0f) popOffDistance = 1.0f; /* M233 not set */

Use braces only when the body is more than one statement. Do not write a braced one-liner, and do not put a single action on the next line without braces.

Title and revision

Every project has revisionHistory.h at the repo root (next to the app or firmware sources). It is the only place the product title and revision are defined:

#define APP_TITLE "Grok Launcher"
#define APP_REVISION "V1.000"

Revision format is Vn.nnn (example V1.000). Bump APP_REVISION in that file when a release meaning changes.

C# WinForms: every form title bar shows APP_TITLE, a space, then APP_REVISION — for this app, Grok Launcher V1.000. Read the defines from revisionHistory.h. Do not hard-code the caption in the designer as the source of truth.

C/C++: #include "revisionHistory.h" and use the same defines wherever the product name is shown to the user.

Installers

Only a Microsoft Installer project may be used: a Visual Studio Setup Project (.vdproj) in the solution, producing a Windows Installer (.msi). Add that installer project to the solution and take Publish Items (or Primary Output) from the app project.

The MSI file name is {SetupProjectName}_{n.nnn}.msi, with {n.nnn} taken from APP_REVISION in revisionHistory.h with the leading V removed. Example: APP_REVISION "V1.000" -> GrokLauncherSetup_1.000.msi. Rename after a successful Setup build; do not hard-code the revision in the .vdproj output name.

Do not use WiX, Inno Setup, NSIS, ClickOnce, MSIX, or any other installer stack.

End of session

- Build (and flash, if this repo flashes) before calling the sitting done.
- Push when the sitting is over, even if the next sitting is "improve it."
- Leave the next goal in one sentence if it is already known.
